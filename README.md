# HXWL-11 散瞳排程台

小儿散瞳验光的滴药登记与仪器排程看板。登记患者、眼别、药品批次、滴眼时刻与眼压；
系统在药效窗口内安排检查，同一仪器同一时段只保留一人；危险病例保留输入、列出原因并锁定，不释放仪器。

## 分层结构

- **档案层 `src/domain/`**
  - `types.ts`：病例、滴眼事件、批次、仪器、排程、检查结果、留档流水等领域模型
  - `catalog.ts`：散瞳药品协议（间隔/起效/窗口）、批次目录、仪器目录、时段网格
- **判定层 `src/domain/`**
  - `rules.ts`：危险病例规则（高眼压 / 批次过期 / 批次未登记 / 滴药间隔不足 / 眼别重叠）
  - `scheduling.ts`：时段占用与"药效窗口内最早空档"纯函数（同一仪器同一 slot 至多一条有效排程）
  - `store.ts`：登记、补滴（作废原排程→按新窗口生成新时段）、重试、检查补录的 reducer
- **本机留档层 `src/storage/`**
  - `stationRepository.ts`：localStorage 读写、清空与演示种子数据
- **界面层 `src/ui/` + `src/App.tsx`**
  - 滴药登记表单、仪器 × 时段网格、病例队列、补滴弹窗、检查补录弹窗、侧边栏（概览/批次/流水）

## 业务规则

- 眼压 > 21 mmHg、批次过期或未登记在册、同眼滴药间隔不足（复方托吡卡胺/环喷托酯 5 分钟）→ 危险隔离
- 危险病例：输入完整保留并逐条列出原因，不生成任何仪器排程（仪器不释放）
- 排程网格：08:00–18:00，每 10 分钟一格；检查只安排在起效后、药效窗口内
- 补滴：原排程立即标记「补滴作废」，安全则按新滴眼的药效窗口重排；危险则继续隔离
- 检查完成后补录双眼瞳孔直径与球镜/柱镜/轴位，排程标记完成并占用留痕

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5111。侧边栏可「载入演示数据」或「清空本机留档」（数据存于浏览器 localStorage）。
